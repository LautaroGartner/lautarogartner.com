# Menu and responsive regression fix

Prepared locally on `codex/menu-responsive-fix-20261005`, based on current production `b67e89041cd04e889e7633f978a60195ae1a8da4`. No push or deployment was performed. Portrait, favicon, APIs, admin and commercial copy are preserved.

All three supplied screenshots were materialized and visually inspected. They show Safari at 390 × 844, the portfolio's three-row mobile header, a separate globe block before the About heading, and the Dennis reference's compact hierarchy.

Live reproduction confirmed that selecting the current page from the menu leaves the modal open with body scrolling locked. Selecting another page starts the route transition behind the still-open modal. The old curved panel takes about 900 ms to settle. Extended keyboard testing exposed focus escaping the dialog. The width matrix also found a 320-pixel footer invitation overflow and, at 741 pixels, an About portrait column that squeezed the biography into a narrow strip and pushed the email beyond the viewport.

The focused fix replaces competing CSS/rAF/timer menu motion with one interruptible curved panel reveal: 600 ms open and 460 ms close, with a smaller 12% edge bend and a 32-pixel content glide. It handles Escape, repeated interrupted opening, current-page selection, route handoff, focus wrapping and return, body lock, history restoration and changes to reduced-motion preference. The mobile header contains the name and a stable 44-pixel menu button; writing and language links remain available in the menu. Native header navigation remains visible with JavaScript disabled. About drops the detached globe, stacks below 1000 pixels and uses proportional desktop columns. The mobile footer heading/button now fit narrow screens, its links wrap, and the large mobile curve is removed.

Validation: build, type checks, syntax and diff checks, and all 25 existing tests passed. Actual Chromium motion tests passed on 1440 × 900 desktop and 390 × 844 touch mobile, with reduced motion tested separately. Checks include moving panel frames, Tab/Shift+Tab trapping, focus return, Escape, close button, five interrupted opens per mode, body scroll lock, current-route selection, outgoing route handoff and Back. Home, About, Work, Contact and Writing had no horizontal overflow at 320, 390, 740, 741, 1024 and 1440 pixels. No-JS navigation and dynamic reduced-motion checks also passed. Desktop, mobile menu, mobile About/Home, and the 741-pixel About screenshots were visually inspected. Safari itself remains untested; the Chromium checks reproduce the supplied viewport and the observed layout failures.

The first final matrix was stopped when network-idle waiting stalled. The completed matrix uses bounded DOM-ready navigation and checks actual application state; its results are recorded in `menu-responsive-evidence.json`. Earlier failed checks led to fixes rather than being counted as passes.
